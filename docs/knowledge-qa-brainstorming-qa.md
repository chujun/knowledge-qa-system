# 个人知识问答系统问答头脑风暴记录

日期：2026-06-06

本文整理本次需求讨论中的关键问答和已确认决策。

## 1. 系统服务对象和场景

问题：这套知识问答系统主要服务谁、解决什么场景？

回答：主要为用户自己服务，用于收集日常生活和工作中碰到的知识，通过问答形式学习，了解知识掌握情况，并根据用户情况进行针对性提问。

决策：系统定位为个人知识学习与掌握度追踪系统。

## 2. 知识来源入口

问题：知识来源主要怎么进入？

回答：当前以对话沉淀为主，后续支持文档、网页导入。

决策：MVP 以对话沉淀为主，后续扩展文档导入。

## 3. 对话内容如何沉淀

问题：一次对话结束后，系统应该如何把内容沉淀为知识？

回答：普通聊天不自动入库。只有当用户主动提出围绕某个知识准备问题和答案时，才纳入知识问答体系。

决策：采用用户主动触发沉淀。

## 4. 知识主题和知识点

问题：知识主题和知识点有什么区别？

回答：知识主题像文件夹，是一个学习范围；知识点像卡片，是主题下具体需要掌握的一条内容。

决策：以知识主题作为学习入口，主题下拆分知识点。

## 5. 题目学习方式

问题：围绕一个知识主题生成问答时，题目偏哪种学习方式？

回答：混合型，需要包括理解型和应用型问答。

决策：题目覆盖理解和应用，并逐步扩展更多认知维度。

## 6. 掌握情况判断方式

问题：系统判断掌握情况时，主要依据什么？

回答：AI 评分 + 用户确认。

决策：系统先自动评分，用户可修正。

## 7. 掌握度记录粒度

问题：掌握度用哪种粒度记录？

回答：组合制，分数 + 标签。

决策：内部保留分数，展示等级和诊断标签。

## 8. 学习掌握维度

问题：除了理解和应用，主流学习理论中还有哪些维度可以判断掌握情况？

回答：记忆识别、区分比较、分析、迁移、判断评价、创造生成、反思元认知等。

决策：MVP 采用五个维度：

```text
理解
区分
应用
分析
评价
```

## 9. 五个维度是否有递进关系

问题：理解、区分、应用、分析、评价有递进关系吗？

回答：有近似递进关系，但不是严格线性。现实学习中可能交叉。

决策：五个维度作为掌握画像维度，不设计成硬性闯关等级。

## 10. 五维出题对 AI 的依赖

问题：五个维度出题是否很依赖大模型能力？

回答：是，但可以用题型模板、质量校验和用户确认约束 AI。

决策：AI 生成题目必须受维度模板和质量校验约束。

## 11. 主题学习是否先拆结构

问题：用户发起知识主题时，系统是否先规划学习结构？

回答：需要先拆知识结构，给出主题大纲、知识点列表、难度层级。但有时用户只是临时接触一个点，不想从 0 系统学习。

决策：系统同时支持主题学习模式和即时掌握模式。

## 12. 即时掌握模式范围

问题：即时掌握模式默认做到哪一步？

回答：解释问题 + 小测 + 可选沉淀。

决策：即时掌握模式生成的题目默认不正式入库，用户确认后可沉淀。

## 13. 题目形式

问题：系统题目形式支持哪些？

回答：主观问答 + 选择题。

决策：MVP 支持主观问答和选择题。

## 14. 答题互动节奏

问题：答题时希望是什么节奏？

回答：两种都支持。生成题库时可以批量看，练习时一题一答。

决策：题库管理支持批量预览，实际练习支持一题一答追问。

## 15. 外部会话沉淀痛点

问题：用户可能在 Claude Code、Codex 中和 AI 对话，发现某个知识点值得测试，是否必须切换到知识问答系统页面？

回答：不希望切换程序，也不希望手动复制粘贴。希望能在 AI Agent 聊天框中说录入知识问答系统。

决策：新增外部会话沉淀模式，通过 API/MCP 接入多套 AI Agent。

## 16. API 和 MCP 区别

问题：API 和 MCP 有什么区别？

回答：API 是给程序调用的业务能力底座；MCP 是给 AI Agent 使用这些能力的协议适配层。

决策：知识问答系统先提供 API，MCP Server 调用 API 并暴露给外部 Agent。

## 17. 外部会话生成结果在哪里确认

问题：Agent 通过 MCP/API 提交会话后，生成结果在哪里确认？

回答：两边都支持。Agent 侧轻量确认，知识问答系统页面详细编辑。

决策：MVP 中 Agent 侧只做轻量确认，详细编辑在系统页面完成。

## 18. Agent 聊天框返回内容

问题：外部 Agent 提交会话后，聊天框里返回哪些信息才够轻量确认？

回答：主题建议、知识点列表、题目预览，并补充确认链接。

决策：Agent 返回主题建议、知识点列表、题目预览和确认/编辑链接。

## 19. 外部会话生成内容状态

问题：外部会话生成的内容在确认前处于什么状态？

回答：待确认。

决策：待确认内容不参与正式练习和掌握度统计。

## 20. 练习入口

问题：知识主题确认后，系统如何组织练习任务？

回答：按主题、薄弱程度、错误集。

决策：MVP 练习入口包括主题练习、薄弱练习和错误集复盘。

## 21. 知识领域

问题：是否需要知识领域，如历史、计算机、AI、摄影？

回答：需要。

决策：新增知识领域，层级为领域 -> 主题 -> 知识点。

## 22. 知识领域如何维护

问题：知识领域手动维护还是系统推荐？

回答：系统推荐领域，用户确认。

决策：领域归类采用系统推荐 + 用户确认。

## 23. 错误集

问题：错误集主要记录什么？

回答：组合错误集，记录错题、薄弱知识点和错误原因。

决策：错误集用于复盘为什么没掌握，而不只是重做错题。

## 24. 答题后学习建议

问题：AI 评分后是否生成下一步学习建议？

回答：需要详细建议。

决策：评分反馈包括缺失点、推荐复习知识点和下一道追问题。

## 25. 标准答案版本化

问题：标准答案是否需要版本化？

回答：需要版本化，便于追踪审计。

决策：答题记录绑定当时使用的标准答案版本。

## 26. 审计范围

问题：哪些内容需要审计记录？

回答：完整审计，生成、确认、编辑、答题、评分、修正、归档都记录。

决策：MVP 可先实现事件日志。

## 27. 用户修正 AI 评分

问题：用户修正 AI 评分时，系统如何处理？

回答：保留 AI 评分、用户评分和差异原因，实现双向评价。

决策：用户确认评分用于掌握度，差异原因用于评估 AI 评分质量。

## 28. 学习目标

问题：是否需要学习目标？

回答：暂时不需要。

决策：MVP 不做学习目标。

## 29. 多用户

问题：是否需要支持多用户？

回答：未来可能多用户，但 MVP 单用户。所有业务领域模型加用户维度。

决策：核心对象预留 user_id。

## 30. 正式入库概念

问题：正式入库是什么业务概念？

回答：生成出来的学习内容从待确认状态，经过用户确认后，正式成为知识问答体系的一部分。

决策：正式入库后才参与正式练习、掌握度、错误集和版本审计。

## 31. 正式入库触发规则

问题：AI 生成内容什么情况下从待确认变成正式入库？

回答：默认待确认。用户明确说直接确认/直接入库时，可以跳过确认页。

决策：默认确认，明确授权可直接入库。

## 32. 来源引用和模型元数据

问题：是否需要保留来源引用？

回答：需要，并且题目、答案还要记录 AI Agent 和大模型来源。

决策：保留来源引用、生成溯源、Agent、模型、提示词版本和参数。

## 33. AI Agent 和模型质量分析

问题：MVP 阶段需要做到什么程度？

回答：先只记录元数据。

决策：MVP 不做统计页面，先保留数据。

## 34. 题目多次生成和版本

问题：同一知识点题目是否允许多次生成、替换或追加？

回答：完整版本化。

决策：题目、答案、评分规则都版本化，并保留生成来源。

## 35. 知识点掌握度汇总

问题：知识点掌握度如何汇总？

回答：综合掌握画像。

决策：五维分数、最近表现、错误原因、用户修正共同形成掌握画像。

## 36. 针对性提问策略

问题：针对性提问优先策略是什么？

回答：综合策略，薄弱维度 + 错题知识点 + 近期学习 + 难度递进。

决策：MVP 先做主动练习、答题后追问、即时掌握。

## 37. 针对性提问题目来源

问题：针对性提问用的是已入库题目还是随机生成题？

回答：不是纯随机，也不只限原题。来源包括已入库题目、基于知识点的变式题、即时生成题。

决策：正式练习优先用已入库题，追问可生成临时变式题。

## 38. 临时题入库与掌握度

问题：临时题答完后如何处理？

回答：如果用户觉得有价值，可确认入库；否则只保留学习记录，不进入正式题库。

决策：临时题未确认不计入长期掌握度；确认入库时由用户选择是否补计入。

## 39. 题目难度

问题：题目难度如何定义？

回答：最终选择五档难度。

决策：认知维度和难度等级分开记录，难度为 1-5。

## 40. 每个知识点初次生成题目数量

问题：每个知识点初次生成多少题？

回答：按知识点复杂度决定，但规则必须明确，防止 AI 瞎生成。

决策：

```text
简单知识点：2 题
中等知识点：3-4 题
复杂知识点：5-7 题
```

生成前必须先判断复杂度、理由、建议题量和覆盖维度。

## 41. 题目质量校验

问题：题目生成后是否需要质量校验？

回答：必须做生成-校验-修正循环。

决策：题目生成后进入规则校验、AI 校验、自动修正和用户确认。

## 42. 质量校验由谁做

问题：质量校验由谁来做？

回答：规则校验 + AI 校验 + 用户最终确认。

决策：MVP 可先用同模型复核，后续保留不同审核模型信息。

## 43. 质量校验输出

问题：质量校验输出什么结果？

回答：完整校验报告，并补充质检大模型和 AI Agent 元数据。

决策：记录相关性、维度匹配、难度匹配、清晰度、可评分性、答案充分性、重复度、实用性、来源支撑等指标，以及校验 Agent 和模型。

## 44. 自动修正次数

问题：质量校验不通过时，自动修正最多几次？

回答：最多 2-3 次。

决策：超过次数后进入待人工处理。

## 45. 质量校验不通过如何处理

问题：不通过时如何处理整批内容？

回答：分题处理。

决策：每道题独立校验，通过保留，失败自动修正，仍失败则待人工处理。

## 46. 质检通过标准

问题：质检通过标准是什么？

回答：无硬性失败项 + 核心指标达标 + 综合质量分达标。

决策：

```text
通过：综合分 >= 85，核心指标均 >= 75
警告通过：综合分 80-84，核心指标均 >= 70
不通过：综合分 < 80，或核心指标 < 70，或触发硬性失败项
```

## 47. 来源支撑强制范围

问题：来源支撑应该对哪些来源强制要求？

回答：按题目类型决定。

决策：事实、概念、操作类强制；评价、反思类弱约束但需说明依据。

## 48. 来源可信度

问题：是否区分知识来源可信度？

回答：来源可信度可配置，系统给默认值。

决策：默认可信度 + 用户可调整。

## 49. 来源冲突

问题：多个来源对同一知识点说法冲突时如何处理？

回答：综合处理。优先高可信来源，保留冲突说明，由用户确认后更新标准答案。

决策：冲突不能自动覆盖标准答案。

## 50. 方案选择

问题：是否开始整理 2-3 套业务方案？

回答：选择方案 C。

决策：采用带外部 Agent/MCP 接入和审计溯源的知识问答平台。

## 51. 核心知识点讲解

问题：答案和题目涉及核心知识点讲解，是否纳入业务场景？

回答：需要纳入。

决策：题目和答案不仅用于评分，也用于讲解核心知识点。

## 52. 核心知识讲解出现时机

问题：核心知识点讲解什么时候出现？

回答：两种都支持。新学时先讲再测，复习时先测再讲。

决策：学习模式先讲后测，练习模式先测后讲。

## 53. 核心知识讲解版本化

问题：核心知识讲解是否版本化和溯源？

回答：需要版本化 + 来源引用 + 生成模型/Agent 元数据。

决策：核心讲解和题目、答案一样可审计。

## 54. 核心知识讲解粒度

问题：核心知识讲解绑定在哪里？

回答：知识点讲解 + 题目补充讲解。

决策：知识点有通用讲解，题目有针对本题的补充解释。

## 55. 核心知识讲解结构

问题：核心知识讲解内容结构是否固定？

回答：固定结构 + 可扩展字段。

决策：MVP 先统一结构，后续按知识类型细化。

## 56. 知识类型

问题：当前业务模型是否有知识类型属性？

回答：之前没有，应该补上。

决策：知识类型作为知识点属性。

## 57. MVP 知识类型

问题：MVP 是否采用六类知识类型？

回答：可以。

决策：

```text
概念类
操作类
原理类
场景应用类
方案评价类
事实信息类
```

## 58. 不同知识类型讲解模板

问题：不同知识类型是否采用不同讲解模板？

回答：可以，后续再细分。

决策：MVP 按六类知识类型配置不同核心讲解模板。

## 59. 当前总方案

最终确认：整体方案采用方案 C，增加核心知识讲解、知识类型、版本化、溯源、质量校验、外部 Agent/API/MCP 接入、掌握画像、错误集和正式入库机制。

## 60. 字段命名和时间属性

问题：业务对象字段是否需要统一规范？

回答：所有业务对象补充创建时间、更新时间属性；所有字段使用英文名，并补充简体中文名。

决策：业务建模文档中的核心业务对象字段采用“英文字段名 / 简体中文名 / 说明”的表格形式，并为每个对象保留 `created_at` 和 `updated_at`。

## 61. 掌握画像分析层级

问题：掌握画像是否可以针对知识领域、知识主题、知识点等不同维度分析？

回答：可以。掌握画像不应只绑定知识点，也要支持领域和主题层面的汇总分析。

决策：`MasteryProfile` 采用可挂载模型，通过 `target_type` 和 `target_id` 支持领域、主题、知识点三个层级。知识点画像聚合为主题画像，主题画像聚合为领域画像。

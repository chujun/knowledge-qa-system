## 阶段：掌握画像和针对性提问细化

阶段结论：

```text
掌握画像采用知识点、主题、领域三级模型。
知识点画像由答题记录、题目维度、难度、近期表现、用户确认评分和错误原因共同计算。
主题画像由知识点画像聚合，领域画像由主题画像聚合。
针对性提问优先使用正式题库，必要时生成临时变式题；临时题未经用户确认不进入长期画像。
```

已确认事项：

```text
掌握维度为理解、区分、应用、分析、评价。
掌握度采用分数 + 等级 + 诊断标签。
用户修正 AI 评分后，以用户确认评分作为长期画像依据。
临时题不默认计入长期画像。
临时题确认入库时，由用户选择是否补计入历史答题记录。
```

待确认事项：

```text
五维分数权重是否需要用户可配置。
近期表现窗口使用最近 N 次答题，还是最近 N 天。
综合等级阈值是否需要后续按用户习惯调整。
```

风险点：

```text
如果只做简单平均，掌握画像会忽略题目难度、近期改善和用户修正。
如果针对性提问过度依赖临时生成题，可能降低题库稳定性和审计质量。
```

```text
进入安全设计，生成 docs/knowledge-qa-security.md。
```

## 1. 掌握画像层级

系统支持三级掌握画像：

```text
知识点级 MasteryProfile：
回答“我对某个具体知识点掌握得怎么样？”

主题级 MasteryProfile：
回答“我在某个知识主题下整体掌握得怎么样？”

领域级 MasteryProfile：
回答“我在某个知识领域下整体掌握得怎么样？”
```

聚合方向：

```text
AnswerAttempt
-> KnowledgePoint MasteryProfile
-> KnowledgeTopic MasteryProfile
-> KnowledgeDomain MasteryProfile
```

## 2. 知识点级掌握画像计算规则

输入数据：

```text
AnswerAttempt
Question
QuestionVersion
AnswerVersion
ScoringRubricVersion
ErrorSet
用户确认评分
题目认知维度
题目难度等级
```

只纳入：

```text
affects_mastery = true 的答题记录。
正式入库题目的答题记录。
用户确认补计入的临时题历史答题记录。
```

不纳入：

```text
未确认临时题。
被归档且不再有效的异常答题记录。
用户明确选择不计入长期画像的答题记录。
```

单次答题有效分：

```text
effective_score = user_confirmed_score 优先，否则使用 ai_score
```

维度分：

```text
某维度分 = 该维度下有效答题分的加权平均
```

加权因素：

```text
题目难度
近期表现
用户确认评分
错误原因
```

## 3. 主题级掌握画像聚合规则

主题级画像由主题下所有知识点画像聚合。

聚合输入：

```text
主题下 confirmed 知识点
每个知识点的五维分
每个知识点的重要性
每个知识点的答题覆盖度
最近练习时间
错误集活跃数量
```

默认规则：

```text
主题某维度分 = 主题下知识点该维度分的加权平均
```

权重建议：

```text
知识点复杂度越高，权重越高。
答题覆盖度过低的知识点降低置信度。
近期有大量错误集的知识点提高关注权重。
```

主题画像输出：

```text
五维分
综合分
薄弱维度
薄弱知识点
错误原因摘要
下一步练习建议
```

## 4. 领域级掌握画像聚合规则

领域级画像由领域下所有主题画像聚合。

聚合输入：

```text
领域下 confirmed 主题
每个主题的五维分
主题下知识点数量
主题最近练习时间
主题错误集活跃数量
```

默认规则：

```text
领域某维度分 = 领域下主题该维度分的加权平均
```

领域画像用于：

```text
查看整体学习短板。
发现某个领域长期薄弱维度。
选择跨主题复习方向。
```

## 5. 五维分数权重

MVP 默认五个维度等权：

```text
理解：20%
区分：20%
应用：20%
分析：20%
评价：20%
```

综合分：

```text
overall_score =
  understanding_score * 0.2
  + differentiation_score * 0.2
  + application_score * 0.2
  + analysis_score * 0.2
  + evaluation_score * 0.2
```

后续可扩展：

```text
按知识类型调整权重。
操作类提高应用权重。
方案评价类提高分析和评价权重。
概念类提高理解和区分权重。
```

## 6. 题目难度对掌握分的影响

题目难度为 1-5。

难度权重建议：

```text
1：0.8
2：0.9
3：1.0
4：1.1
5：1.2
```

加权思路：

```text
高难度题答得好，应更能证明掌握。
低难度题答得好，只能证明基础掌握。
高难度题答差，不应过度拉低基础维度，但应进入薄弱提示。
```

草案公式：

```text
weighted_score = effective_score * difficulty_weight
```

分数上限：

```text
weighted_score 不超过 100。
```

## 7. 最近表现对掌握分的影响

MVP 采用最近表现加权。

建议窗口：

```text
最近 10 次相关答题记录。
如果不足 10 次，则使用全部有效记录。
```

近期权重：

```text
最近 3 次：权重 1.2
中间 4 次：权重 1.0
更早 3 次：权重 0.8
```

目的：

```text
体现学习改善。
避免很久以前的错误长期拖累画像。
避免一次偶然高分完全覆盖历史薄弱。
```

## 8. 用户修正评分对掌握分的影响

规则：

```text
如果用户确认评分存在，长期画像使用 user_confirmed_score。
如果用户未确认，使用 ai_score，但标记置信度较低。
如果用户修正原因是“AI 误判”，该记录可用于模型评分质量分析。
如果用户修正原因是“标准答案不完善”或“评分规则不合理”，该题应进入待复核。
```

用户修正后的影响：

```text
更新 AnswerAttempt。
记录 score_diff_reason。
触发 MasteryProfile 重算。
可生成 AuditEvent。
可更新模型评分质量统计。
```

## 9. 临时题不计入长期画像规则

临时题来源：

```text
即时掌握小测题
答题后追问生成的临时变式题
外部会话刚生成但未确认的检测题
```

默认规则：

```text
临时题 AnswerAttempt.affects_mastery = false。
临时题可用于当次反馈。
临时题不进入正式错误集。
临时题不参与知识点、主题、领域长期画像。
```

## 10. 临时题确认入库后补计入规则

用户确认临时题入库时，需要选择：

```text
是否将已有临时题答题记录补计入长期掌握画像。
```

选择是：

```text
将对应 AnswerAttempt.affects_mastery 更新为 true。
绑定正式入库后的题目版本、答案版本、评分规则版本。
触发知识点、主题、领域画像重算。
```

选择否：

```text
临时答题记录继续只作为学习记录。
该题后续正式练习记录才计入长期画像。
```

## 11. 错误原因标签体系

基础错误原因：

```text
concept_misunderstanding：概念理解错误
concept_confusion：概念混淆
missing_key_point：遗漏关键点
application_gap：应用不足
analysis_incomplete：分析不完整
evaluation_lacks_criteria：评价缺少标准
source_unaware：不了解来源依据
expression_unclear：表达不清
operation_step_missing：操作步骤缺失
condition_ignored：忽略前置条件
```

错误原因用途：

```text
生成 ErrorSet。
聚合到 MasteryProfile.error_reason_summary。
驱动针对性提问策略。
反向评估题目和评分规则质量。
```

## 12. 针对性提问策略

针对性提问不是单独题库，而是题目选择和生成策略。

输入：

```text
当前练习目标
知识点/主题/领域掌握画像
薄弱维度
错误集
最近答题表现
题目难度
题目来源状态
用户当前指令
```

优先级：

```text
1. 用户明确指定的主题、知识点或错误集。
2. 薄弱维度。
3. 活跃错误集相关知识点。
4. 最近学习但掌握不稳的内容。
5. 难度递进。
```

输出：

```text
下一道题或一组题
题目来源
认知维度
难度等级
为什么问这题
期望验证什么
```

## 13. 优先使用已入库题目的策略

正式练习中优先使用：

```text
confirmed 状态题目。
有 active QuestionVersion、AnswerVersion、ScoringRubricVersion 的题目。
有质量校验记录的题目。
与当前薄弱维度匹配的题目。
用户近期未重复做过的题目。
```

避免：

```text
连续重复同一题。
连续只问同一维度。
长期只问低难度题。
使用未确认题目影响长期画像。
```

## 14. 生成临时变式题的条件

允许生成临时变式题：

```text
已入库题目不足。
用户连续答对原题，需要迁移检测。
用户答错后需要追问。
需要验证应用、分析、评价等高阶维度。
用户明确要求“换个场景考我”。
```

临时变式题要求：

```text
必须基于已确认知识点和来源。
必须有标准答案和评分规则。
默认 affects_mastery=false。
答完后可由用户确认入库。
```

## 15. 下一道追问题生成规则

触发条件：

```text
用户答错。
用户得分低于 70。
AI 诊断存在明显薄弱标签。
用户主动要求继续追问。
```

追问生成规则：

```text
如果理解不足，生成更基础的解释型问题。
如果区分混淆，生成对比题。
如果应用不足，生成具体场景题。
如果分析不足，生成原因拆解题。
如果评价不足，生成方案取舍题。
```

追问输出：

```json
{
  "next_question_type": "generated_variant",
  "cognitive_dimension": "application",
  "difficulty_level": 3,
  "reason": "上一题显示用户理解概念，但没有掌握具体配置方式。",
  "question_stem": "如果 workflow 只想在 main 分支 push 时触发，应该怎么配置？"
}
```

## 16. 阶段复盘建议规则

触发时机：

```text
完成一组练习。
用户查看主题或领域画像。
错误集积累到一定数量。
用户主动请求复盘。
```

复盘输出：

```text
本轮总体表现
五维分变化
主要薄弱维度
主要错误原因
建议复习知识点
下一组推荐题
是否建议沉淀临时题
```

复盘示例：

```text
本轮 GitHub Actions 练习中，理解维度表现较好，但应用和分析偏弱。
主要问题是触发条件的配置细节不完整。
建议下一轮优先练习 workflow trigger 的应用题和故障分析题。
```

## 17. 掌握等级建议

```text
90-100：熟练
75-89：基本掌握
60-74：模糊
40-59：较弱
0-39：未掌握
```

等级说明：

```text
熟练：能解释、应用、分析并做基本评价。
基本掌握：理解和常规应用可行，但高阶分析或评价可能不足。
模糊：能说出部分内容，但不稳定。
较弱：关键点缺失，应用困难。
未掌握：无法解释或明显错误。
```

## 18. 掌握画像验收点

```text
知识点画像能根据答题记录计算五维分。
主题画像能由知识点画像聚合。
领域画像能由主题画像聚合。
用户确认评分优先于 AI 评分。
临时题默认不影响长期画像。
临时题确认入库后可选择补计入。
错误原因能聚合到画像摘要。
针对性提问能优先选择薄弱维度和错误集。
系统能说明“为什么问这道题”。
```
